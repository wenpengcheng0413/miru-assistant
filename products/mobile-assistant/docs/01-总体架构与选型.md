## 2. 技术栈（Q1）

| 层 | 选型 | 理由 | 备选 |
|----|------|------|------|
| 手机客户端 | **Flutter** (iOS) | 自签 IPA 可用、UI 效率高、以后可出 Android 版 | 原生 SwiftUI |
| 后端框架 | **FastAPI + Uvicorn** | 原生 async、WebSocket 一等公民、生态成熟 | aiohttp |
| LLM 大脑 | **DeepSeek V4 Flash 0731**（`deepseek-v4-flash`） | 已在用；1M 上下文、函数调用、流式；输入缓存命中 0.02 元/M | 备用 deepseek-v4-pro（贵 3 倍，仅在推理困难时） |
| 本地 STT | **SenseVoice-Small**（sherpa-onnx） | 免费不限量、普通话/粤语/中英混合一个模型、CPU 实时、Windows 官方支持 | faster-whisper small（本机已有，兜底） |
| TTS | **MiniMax speech-02-turbo**（流式） | 低延迟、中文自然、支持克隆、句级流式 | CosyVoice v3.5-flash（更便宜）；edge-tts（免费兜底） |
| 记忆存储 | **SQLite**（结构化 + 关键词检索） | 零运维、本地；个人数据量下毫秒级 | 后期加向量索引（bge-small-zh ONNX 本地嵌入） |
| 成本账本 | SQLite + pricing.yaml | 价格表与代码分离，改价不用改代码 | — |
| 手机↔PC 通道 | 局域网直连 → **Tailscale** →（远期）frp+VPS | WireGuard 加密、免端口映射、可发真证书 | ZeroTier / Cloudflare Tunnel |
| 任务调度 | APScheduler（现有依赖） | 日后主动任务（早报）复用 | Windows 计划任务（V1 在用） |
| 包管理 | pip + venv（沿用现有 `venv`） | 仓库现状一致 | uv（可选迁移） |

**明确不做**：不用 LangChain/LlamaIndex 等 agent 框架——工具循环、记忆、成本控制都是本项目的核心逻辑，用 200 行自研代码完全可控；不用本地 LLM 做大模型推理（DeepSeek 已够便宜，本地大模型占用 GPU/内存收益低）。

## 3. 本地运行 vs 调用 API 的边界（Q22）

原则：**高频、敏感、可离线的东西本地做；低频、重推理、需要外部世界的东西走 API。**

| 能力 | 本地 | 云端 API | 理由 |
|------|------|----------|------|
| 语音识别（用户说的话） | ✅ SenseVoice | ✗ | 每天高频调用、按量付费无底；**用户语音不上传** |
| 大脑推理（意图/回答） | ✗ | ✅ DeepSeek | 本地大模型成本/维护远超 API 费用 |
| 语音合成（Miru 的话） | 兜底 edge-tts | ✅ MiniMax | 需要音色克隆与自然度；按量便宜 |
| 记忆嵌入向量 | ✅ bge-small-zh ONNX | ✗ | 免费且数据敏感 |
| 微信数据解密/读取 | ✅ 本地（现有模块） | ✗ | 合规与隐私红线 |
| 图片理解 VLM | 解密/提取本地 | ✅ 可选 VLM API | 图片内容理解需要视觉模型（见 04 文档） |
| 成本账本 | ✅ SQLite | ✗ | 纯本地计算 |
| 聊天语音消息转写 | ✅ faster-whisper（已有） | ✗ | 与 V2 一致 |

## 4. FastAPI 后端架构（Q3）

`server/miru_server/` 分层（单向依赖）：

```
api/         HTTP/WS 入口层：ws.py（/ws/session）、rest.py（/api/*）
core/        会话管线：pipeline.py（主循环）、llm.py（DeepSeek 流式客户端）、
             splitter.py（句级分块）、events.py（事件模型）
stt/         base.py + sensevoice.py + whisper_stt.py + vad.py（全部本地，可插拔）
tts/         base.py + minimax_tts.py + edge_tts.py + queue.py（句队列+预取）
tools/       base.py + registry.py + builtin/（系统/记忆/成本/微信）
memory/      store.py（CRUD）、extractor.py（会话后自动沉淀）
persona/     builder.py（yaml → system prompt）
cost/        tracker.py（用量入账）、pricing.py（价格表与计算）
db/          database.py + models.py（SQLAlchemy 2.0 + SQLite WAL）
config.py    配置加载（yaml + ${ENV} 环境变量解析）
```

**一次语音请求的生命周期**：

1. WS 握手（token 鉴权）→ `Session` 对象创建/恢复（加载对话历史）
2. 手机推 PCM 帧 → VAD 判静音断句 → 调 STT 引擎出**部分结果**（边说边显示）与**最终文本**
3. `Pipeline.run(user_text)`：
   - 组装 messages：`[system(persona+memory+规则)] + [历史消息(截断)] + [user]`
   - DeepSeek 流式请求（附工具 schema）：
     - 文本增量 → 事件转发 + 句级分块 → TTS 队列
     - `tool_calls` → 注册表执行（带确认/超时/结果裁剪）→ 结果回填 → 继续下一轮（上限 6 轮）
   - 结束：usage 入成本账本 → 后台任务做记忆提取 → 发 `turn_end`
4. 会话消息落库（异步，不阻塞流式）

**关键工程决策**：

- **每连接一个 Pipeline 实例**：会话状态（历史、统计）挂在 WS 连接上，REST 接口只做管理面（记忆/人设/成本查询），避免分布式状态问题。
- **所有外部调用可超时降级**：STT 模型没下载→文本模式照常可用；MiniMax 挂了→edge-tts 兜底；DeepSeek 超时→重试 2 次后报错。任何单点故障都不影响其他链路。
- **微信模块是"可选依赖"**：`import miru.chat_analyzer` 包在 try/except 里，Windows 本机装上就有微信工具，日后迁到 Linux VPS 时自动禁用，其余功能不受影响。

## 5. WebSocket 与 HTTP 的分工（Q8）

| 通道 | 用在哪 | 为什么 |
|------|--------|--------|
| **WS `/ws/session`** | ① 实时语音上行（PCM 帧）② LLM 文本流下行 ③ TTS 音频下行 ④ 工具执行状态 ⑤ 打断信号 | 双向、低开销、保序、无需轮询；音频帧与事件帧可交错 |
| **HTTP `/api/*`** | 会话列表、记忆 CRUD、Persona 编辑、成本报表、健康检查、调试端点（单次 STT/TTS） | 请求-响应语义清晰，适合管理面与 App 设置页；Bearer 鉴权统一 |

规则：**凡是"一次对话过程中实时发生的东西"走 WS，凡是"管理/查询"走 REST。** 不建第二类实时通道（不用 SSE 替代 WS，避免双协议维护成本）。

## 6. iPhone ↔ Windows 安全通信（Q15）

三阶段演进，每阶段只加一层，协议不变：

| 阶段 | 拓扑 | 手机端地址 | 安全 |
|------|------|-----------|------|
| 0 开发 | 同一 Wi-Fi，HTTP 直连 | `http://192.168.x.x:8765` | Info.plist 开 ATS 例外 + `NSLocalNetworkUsageDescription`；仅局域网 |
| 1 推荐 | **Tailscale** 组网 | `https://miru-pc.xxx.ts.net:8765` | WireGuard 端到端加密；`tailscale cert` 发 Let's Encrypt 真证书（免自签信任）；不暴露公网端口 |
| 2 随处可用 | **frp 反代到自己的 VPS** | `https://miru.yourdomain.com` | frps 只转发到 frpc，TLS 终结在后端（certbot 自动续期）；VPS 上不放敏感数据 |

细节：

- **证书**：阶段 1 用 `tailscale cert miru-pc` 拿到 `*.ts.net` 证书（90 天，需脚本续期或改用 Caddy 托管）；注意机器名会进证书透明度公账，机器名不要带个人信息。阶段 2 用 certbot + 域名。
- **鉴权**：WS 握手与 REST 共用 `Authorization: Bearer <token>`，token 从 `MIRU_SERVER_TOKEN` 环境变量读取（默认随机生成并打印，防止空口令裸奔）。手机端 token 存在 Keychain。
- **最小暴露**：后端默认绑定 `127.0.0.1`，配置 `server.host` 才开放 LAN/Tailscale 网卡；**永远不要**把 8765 端口映射到公网 IP 裸奔。
- **iOS 侧注意事项**：自签 IPA（SideStore/LiveContainer）无法用 APNs 推送，所以"Miru 主动找你"只能靠 App 前台时维持 WS 长连接（见 09 文档）。

## 7. 项目目录结构（Q17）

monorepo 按产品划分：手机助手内部包含客户端、后端和专属文档；旧日报/聊天分析作为相邻产品保留。

```
miru-assistant/
└── products/
    ├── mobile-assistant/
    │   ├── app/                       # Flutter 客户端
    │   ├── server/                    # FastAPI 后端
    │   │   ├── miru_server/           # API、管线、STT/TTS、Tool、Memory
    │   │   ├── config/                # 配置模板与本机真实配置
    │   │   ├── scripts/               # 调试与模型下载脚本
    │   │   ├── tests/                 # 后端测试
    │   │   └── data/                  # 数据库、模型、日志（gitignore）
    │   └── docs/                      # 本套工程设计文档
    └── daily-report/
        └── src/miru/chat_analyzer/    # 可选复用的微信离线分析能力
```

**为什么后端独立成 `server/` 而不是塞进日报的 `src/miru/`**：① `miru` 包有 Windows 专属依赖（pymem/pysilk），日后迁 Linux VPS 时装不上；② 后端是长驻服务（uvicorn），日报 CLI 是短命令，生命周期不同；③ 微信工具通过**可选 import** 复用现有模块，两包安装在同一环境时即可互通。

## 8. 关键技术事实（2026-08 调研）

- DeepSeek V4 Flash：输入 1 元/M（缓存命中 0.02 元/M）、输出 2 元/M；工作日 9-12 / 14-18 点（北京时间）**价格 ×2**；thinking 默认开启（推理 token 按输出计费，语音场景必须关）。
- MiniMax speech-02-turbo：SSE 流式返回 hex 音频块，支持 mp3/pcm/flac，10 秒音频即可克隆音色；阿里云百炼渠道约 2 元/万字符。
- SenseVoice：单模型支持 zh/yue/en/ja/ko 自动识别，非自回归架构 CPU 上识别 10 秒音频仅几百毫秒；sherpa-onnx 官方支持 Windows。
- 来源详见 [03 文档](03-语音链路-STT-TTS-LLM.md) 末尾引用。
