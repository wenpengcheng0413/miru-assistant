## Executive Summary

Miru 已在本地等效 2 vCPU / 2GB RAM / 2GB Swap 环境完成 Phase 2 验证。目标是部署单一 Miru Cloud 服务，不加载本地 STT 模型，不运行 Home Node、微信、RTX 或 ComfyUI。

当前最符合“首年低成本 + 长期可预测 + 规格刚好够用”的方案是：

1. **Top 1：阿里云 ECS 经济型 e，2C2G、3M 固定带宽、40G ESSD Entry，99 元/年。** 官方活动页同时声明新购/续费同价，但不同官方页面的活动截止日期出现 2027-03-31 与 2029-03-31 两种表述，购买前必须以订单页和账号资格为准。
2. **Top 2：百度智能云 BCC 经济型 e1，2C2G、3M、40G，92.16 元/年。** 当前官方活动页公开了规格和首购价，但公网 IPv4、流量口径和第二年续费仍需账号态核验，因此属于低价候选而非无条件结论。
3. **Top 3：腾讯云 Lighthouse 2C2G、4M、50G、300G/月，510 元/年。** 网络余量和磁盘更宽，但首年价格明显高于预算优先方案，续费需在校园/购买页确认。

如果阿里 99 元订单页确认广州地域、Ubuntu LTS、固定公网 IPv4、3M 带宽及同价续费，阿里方案应作为默认购买路径。若 99 元资格或地域不可用，百度 92.16 元方案只有在确认公网 IP、月流量和第二年成本后才可替代。腾讯方案适合更看重 4M/50G/300G 网络余量的情况，不适合作为“最低总成本”选择。

华为当前公开的 2C2G Flexus L 为 2Mbps，低于 Miru 的 3Mbps 硬门槛；火山引擎公开的 2C2G 特惠为 1Mbps，亦不合格。历史华为 98 元、腾讯 68 元等信息缺少当前有效、完整的官方结算证据，只保留为促销观察项。

**当前购买建议：**值得进入购买核验窗口，但没有证据表明必须立即抢购。先在不提交订单的前提下完成 Top1/Top2 的账号资格、地域、IPv4、最终支付额和第二年续费核验，再决定是否购买。Phase 3B（服务器初始化）保持未开始。

## Miru Requirements

### 硬门槛

| 项目 | 正式要求 | 说明 |
|---|---:|---|
| CPU | ≥2 vCPU | 2C2G 是当前正式基线 |
| RAM | ≥2GB | 2C4G 只作升级候选 |
| 磁盘 | ≥40GB 持久盘 | 优先 50–60GB；不放微信快照和本地模型 |
| 架构 | x86_64 | 与当前 Linux 镜像和 Docker 验证一致 |
| 系统 | Ubuntu LTS | 推荐 Ubuntu 22.04/24.04 LTS |
| 入口 | SSH root/sudo | SSH 仅密钥登录，不依赖密码登录 |
| 网络 | 稳定公网 IPv4 | 购买页确认是独享/固定还是共享 NAT |
| 带宽 | ≥3Mbps | 低于 3Mbps 不进入正式候选 |
| 流量 | 若限流，≥200GB/月 | 300GB/月更稳妥；确认超额单价 |
| 软件 | Docker Engine + Compose | 一台服务器只运行 Miru |
| 协议 | HTTP、WebSocket、Tailscale | `/ws/node` 只走 Tailnet，不公开 |

### 已验证的负载基线

Phase 2 报告记录：2 vCPU、约 1.86GiB 可见内存、2GiB Swap；API 单路聊天峰值约 99.92MiB，两路合计峰值约 110.10MiB；正常测试无 OOM，Swap 峰值约 0.27MiB。当前 Compose 限制为 API 640MB/1 CPU、Caddy 96MB/0.2 CPU，属于资源隔离上限，不是所有组件可同时打满的容量预算。

尚未完成的 Phase 9 工作包括独立 Attachment Worker、恶意文档炸弹、OOM 后任务失败和真实外部语音 Provider 压测。因此选型不能把整台 2GB RAM 当作可分配给应用的 2GB。

### 调研范围

- 一级：阿里云 ECS/轻量应用服务器、腾讯云 CVM/Lighthouse、华为云 ECS/Flexus L、火山引擎 ECS/活动轻量方案。

- 香港/海外：只比较网络、流量、价格、跨境延迟和免 ICP；不因免备案自动优先。

### 证据等级

- `VERIFIED`：官方公开页面或官方订单页面完整显示规格、地域、期限和价格。
- `ACCOUNT-VERIFICATION-REQUIRED`：官方权益或产品真实存在，但资格、最终价、IPv4 或续费需登录后确认。
- `PROMOTION-CLAIM`：只有活动宣传、历史页面或非官方转载，不能作为确定价格。
- `UNVERIFIED`：无法形成可复核结论。

每条价格记录均应保留检查日期、页面更新时间、活动截止日、地域、规格、磁盘、带宽、流量、是否限购、首购资格和续费条件。促销页与购买页冲突时，购买页优先；无法进入购买页时保留冲突，不自行选择有利数字。

## ECS vs Lightweight

| 维度 | 传统 ECS/CVM/BCC | 轻量 Lighthouse/Flexus/SWAS |
|---|---|---|
| 计费 | 实例、云盘、IP、带宽可能分项 | 资源打包，价格更易预估 |
| 扩容 | CPU、内存、磁盘、网络更灵活 | 套餐固定，部分产品升级受限 |
| 网络 | 可按需购买独立公网和带宽 | 套餐带宽/流量固定，超额另计 |
| 备份 | 快照和云盘组合更灵活 | 通常随套餐或单独购买 |
| 适合 Miru | 阿里 99 ECS 是例外的低价长效方案 | 腾讯 2C2G 套餐操作简单但成本较高 |
| 主要风险 | 分项费用漏算 | 流量、地域和迁移限制 |

Miru 是单用户、低并发、单项目服务，优先选择账单确定性强且带固定公网 IPv4 的方案。不要为了“轻量”而接受 1–2Mbps，也不要为未来可能的附件峰值预购 GPU 或数据库服务。

## China Mainland vs Hong Kong

### 中国内地

- 广东用户优先广州，其次深圳；若没有满足条件的套餐，再比较上海/华东。
- 通过普通域名提供网站/API 时需要 ICP 备案；但 Phase 3A/第一阶段采用 Tailscale `.ts.net`，备案不是当前购买阻塞项。
- 内地节点到广东用户的访问路径和延迟通常更直接，适合 Miru API、WebSocket 和 Home Node 控制面。

### 香港

- 免 ICP、可快速使用普通域名。
- 必须实际核验广东到香港的延迟、丢包、跨境带宽、月流量和超额费用。
- 不能仅凭“香港无需备案”把带宽或流量不足的方案列为优先。
- 除非香港方案在首年、续费和跨境网络均明显领先，否则不进入最终 Top3。

## Coupon Analysis

### Scenario A — 保留阿里 300 元抵扣金

购买阿里 99 元 ECS，不使用抵扣金。首年现金支出 99 元，300 元抵扣金保留；这是默认的机会成本最小方案，前提是 99 元学生机资格和订单页配置成立。

### Scenario B — 消耗抵扣金购买更高规格

只在以下条件同时成立时考虑：

- 抵扣金可用于目标 ECS/系统盘/带宽订单。
- 抵扣后现金支出低于 Scenario A 的可接受预算。
- 目标规格确实需要 2C4G 或更高磁盘/带宽。
- 抵扣金有效期、叠加和未使用余额规则已在结算页确认。

99 元学生机明确不可用 300 元抵扣金，因此不能把两个优惠直接相加。

## Network Analysis

### 带宽

- 3Mbps 是硬门槛，适合文本聊天、WebSocket 流式输出和小型附件，但不适合大规模媒体分发。
- 4–5Mbps 比 3Mbps 有更好的突发余量；200Mbps 峰值只有在套餐不限流量且实际出口策略清晰时才有价值。
- 1–2Mbps 方案不满足正式门槛，即使价格很低也只能做实验。

### 流量

- 200GB/月是最低接受值，300GB/月是更稳妥的起点。
- 必须确认流量是出站、双向还是总量，是否每月重置，超额是否按 GB 收费。
- 外部 STT/TTS 和 DeepSeek 流量会占用公网出口；聊天文本消耗小，但附件/音频会放大出口流量。

### IPv4 与 WebSocket

- 购买页必须显示固定公网 IPv4 或可稳定绑定的 EIP。
- API 端口不直接暴露；Caddy 负责 443/HTTPS 和 WebSocket 反代。
- `/ws/node` 只允许 Tailnet 路径，不能因供应商允许公网 IPv4 就公开该端点。
