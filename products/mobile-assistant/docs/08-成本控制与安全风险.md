# 08 · API 成本控制与安全风险（Q14 / Q23 / Q24）

## 1. API Cost Tracking 设计（Q14）

### 1.1 埋点位置（cost/tracker.py）

| 记账点 | 数据来源 | 费用公式 |
|--------|----------|----------|
| LLM 每轮结束 | DeepSeek stream 末帧 `usage`（`stream_options.include_usage`） | `(miss×1.0 + hit×0.02 + out×2.0) / 1M × 高峰系数` |
| TTS 每句 | MiniMax 响应 `usage` 或按字符数 | `chars / 10000 × 2.0 元` |
| VLM 每图 | 按张数 | pricing.yaml 可配 |
| 本地 STT / 嵌入 | 固定 0（打标 `provider=local`，报表里可见"替你省了多少"） | — |

价格全部来自 `config/pricing.yaml`（改价只改 yaml），高峰时段（工作日 9-12 / 14-18 北京）自动 ×2。usage 缺失时用字符数/4 估算并打 `estimated` 标记。

### 1.2 报表与预算

- REST：`/api/cost/report?days=7|30` → 按天/按模型/按 provider 分桶；手机设置页有成本面板（折线图）
- 预算：`PUT /api/cost/budget` 设月限额 → 每轮 LLM 调用前检查：
  - 用量 <80%：静默
  - 80-100%：`server_note` "本月 AI 预算已用 85%（127/150 元）"——Miru 会在回答末尾提醒
  - ≥100%：默认仍放行但每次提示；可配 `budget.hard_block: true` 直接拒绝并说明
- **成本是对话的一等公民**：`turn_end` 事件带 `cost_rmb`，用户随时能看到"这句话花了 0.02 元"；`api_cost_report` 工具让 Miru 自己也能回答"这个月花了多少"

### 1.3 个人用量估算（按需求书的使用强度）

| 项 | 假设 | 月成本 |
|----|------|--------|
| DeepSeek 对话 | 100 轮/天 × 30，平均 2k token 输出 + 4k 输入（多轮缓存命中率高） | ≈ 25-35 元 |
| TTS | 同量级，45 万字符/月 | ≈ 9 元（MiniMax） |
| VLM 看图 | 100 张/月 | ≈ 2-3 元 |
| **合计** | | **≈ 40-50 元/月**；预算 150 元绰绰有余 |

## 3. 隐私、安全与微信数据风险（Q24）

### 3.1 风险清单与缓解

| # | 风险 | 等级 | 缓解措施 |
|---|------|------|----------|
| 1 | **微信数据合规**：逆向读取聊天库违反微信 ToS，有封号/法律风险 | 🔴 | 仅限个人使用、自用数据；只读不写、不批量外发；README 明示风险自担 |
| 2 | **聊天内容发给 DeepSeek**（第三方看到原始消息） | 🔴 | 默认 `aggregates` 档位只送统计；`raw` 档需显式开启且每轮提示；未来敏感分析可切本地 LLM |
| 3 | 解密密钥/库文件泄露（database_keys.yaml、all_keys.json） | 🟠 | 已 gitignore（沿用 V2 惯例）；建议 Windows 用户目录加密；别把密钥放进云备份 |
| 4 | 后端端口裸奔公网 | 🟠 | 默认绑 127.0.0.1；公网只走 Tailscale/frp+TLS；WS/REST 强制 Bearer token（空 token 拒绝启动） |
| 5 | API key 泄露（.env 误提交） | 🟠 | .env gitignore + `.env.example` 模板；key 只存环境变量与手机 Keychain |
| 6 | 语音上行被中间人窃听（局域网明文 HTTP 开发期） | 🟡 | 正式使用必须 HTTPS（tailscale cert / LE）；开发期仅限自家 Wi-Fi |
| 7 | TTS 云端收到 Miru 的回答文本 | 🟡 | 回答本身非敏感（但含项目信息），接受；本地 CosyVoice 是最终兜底选项 |
| 8 | LiveContainer 宿主风险（第三方构建可读钥匙串；guest 不隔离） | 🟡 | 只用官方构建；容器内只装自研 App |
| 9 | 成本失控（bug 死循环调用工具） | 🟡 | 工具循环上限 6 轮、超时 30s、结果裁剪、预算硬顶——四道闸 |
| 10 | 自动记忆写错/写脏 | 🟢 | 全部可查可删；auto 来源一键清空；敏感信息提取规则里明令禁止记录密钥/密码 |
| 11 | 手机丢失 → 他人可语音调用工具 | 🟢 | token 存 Keychain + 可选"高危工具需确认"；远期加 FaceID 门禁 |

### 3.2 三条铁律

1. **聊天记录默认不出 PC**——原始消息只在本地读、本地统计、本地转写；发给 LLM 的一律按档位过滤。
2. **所有外部通道强制鉴权**——没有"信任内网就免密"的幻想。
3. **一切可审计**——api_usage 记录每一次调用与费用；tool_calls 记录每次工具调用参数与结果；memory 记录来源。

### 3.3 已知残余风险（诚实声明）

- 微信逆向后本地存有全部解密数据，PC 被入侵=聊天记录失守（与 V2 现状相同，未引入新风险）
- DeepSeek 为第三方模型，`samples/raw` 档位下发送内容受其隐私政策约束——这是"用云端大脑换智能"的固有代价，用户按档位自选
